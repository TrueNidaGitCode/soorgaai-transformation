2. Aria — Data Readiness

Simulated · no live product yet

Cob's Data Readiness domain already identified exactly which datasets this opportunity needs. Aria's real job would be closing the gap between what's identified and what's actually connected — for this demo, that step was done by hand, not by a running product.

Datasets Cob identified as required

Test Execution and Defect Records HIGH Jira, Polarion, TestRail
Flashing Logs and Diagnostic Traces HIGH Internal log repositories, Campaign Manager
Pre-analysis Business Objectives HIGH Confluence, program documentation
OTA ECU Product Configuration HIGH Product configuration DB, Polarion
Engineering Knowledge Base MEDIUM Confluence, historical analysis docs
OTA System Architecture Artifacts MEDIUM System architecture docs, engineering portal

What actually happened here: we don't have access to KPIT's real Jira, Polarion, or log repositories, so Aria's role was simulated manually — 14 synthetic, representative defect records were written and seeded (seed_defect_records.mjs) to stand in for what Aria would have pulled from the real systems above.

What actually runs this capability, provisioned with zero new code — Svarg's own existing platform infrastructure, originally built for Cob, reused as-is for Eame's matching and retrieval.
