# Purpose

This layer supplies education technology context for sequencing AI initiatives:
what makes something a defensible starting point in this industry, and which
apparently attractive initiatives should be deliberately deferred.

Prioritisation method and output structure are inherited from the Core Asset.

---

## AI Implementation Prioritization

Two constraints dominate sequencing here, and both push toward smaller first
steps than an enterprise plan would suggest.

**There is no implementation team.** The people who would run a pilot are the
same people teaching classes. An initiative requiring sustained internal effort
will stall, however sound it is.

**The evaluation window is a term, not a year.** If value is not visible within
one enrolment cycle, the initiative is judged to have failed regardless of its
long-run merit.

So the first initiative should be one where the data already exists, the
workflow already exists, and a human already performs the task — AI removes
effort from something happening today rather than introducing something new.

# Prioritisation Criteria for Education Technology

Weight these more heavily than generic effort/impact scoring:

1. **Data already captured.** Attendance and payments are recorded because the
   business requires it. Initiatives built on them start immediately.
   Initiatives requiring new capture start after a behaviour change that
   usually does not happen.
2. **Existing workflow to attach to.** The output must land where someone
   already looks. A new place to look is a new habit, and new habits fail.
3. **Unpleasantness relieved.** Adoption tracks disliked-work removed more
   reliably than time saved. Fee follow-up and repetitive parent messaging are
   the strongest candidates on this criterion.
4. **Reversibility.** An initiative a teacher can ignore on a bad day will be
   trusted. One that blocks the class if it misbehaves will be switched off.
5. **Independence from data cleanup.** Anything gated on tidying historical
   records inherits an unbounded prerequisite.
6. **Seasonal fit.** Prefer initiatives whose value recurs weekly over those
   that matter only at admissions.

# Typical Sequencing

A defensible order for a first year, adjusted to the institution:

**Start with** a single administrative task that is high-frequency, disliked,
and already captured as data — most often fee follow-up or routine parent
communication. It proves value inside one term and requires no new data.

**Follow with** pattern detection over the same data now flowing reliably —
attrition and disengagement warning. This is materially more valuable, but only
once someone trusts the underlying records, and only once an intervention is
defined.

**Then** extend to scheduling assistance and enquiry handling, which touch more
of the operation and therefore need the credibility earned earlier.

**Defer** anything assessing student capability or progression. It is the most
requested and the least suitable first step: highest regulatory exposure,
highest parental sensitivity, and the area where instructors are least willing
to accept a machine's judgment before trust exists.

# Effort Realities in This Industry

- Integration effort is usually dominated by messy institution-specific data,
  not by modelling.
- Change management is small in headcount but high in significance: convincing
  three teachers is the whole rollout, and one vocal sceptic can end it.
- Infrastructure expectations are low; these organisations will not run
  anything themselves. Delivery must be hosted and operated for them.
- Budgets are small and seasonal, aligned to fee collection cycles.
